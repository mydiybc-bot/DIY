# 平板外語食譜：回讀檢查說明（獨立回讀員用，2026-10-24）

你沒有參與翻譯。你是第二雙眼睛：逐頁把原文英文和譯文對照著讀，找出會讓客人做錯或看不懂的問題。經營者的規則是「Claude 自己檢查通過就放行，主廚不看」，所以你這關就是放行前的最後一關，寧可多擋、不要放過。

## 輸入
資料夾 `~/Desktop/Claude/Code/資料交換/輸出/暫存/i18n_claude/`，同一個 tag 的：
- `<tag>.src.json`：原文（`slides[].t/.h`、`name`、`pres`、`dict` 詞典、`missing`）
- `<tag>.tr.json`：譯文（`slides[]`、`name`、`pres`、`dict`＝新翻的詞）
- `<tag>.brief.txt`：翻譯規則

## 只翻改到的頁（2026-11-05 起）
`src.json` 有 `"partial": true` 時，`slides` 只有字改過的頁（`k` 是原頁碼，可能跳號），其他頁沿用已放行的上一版、不用看。`checked_pages` 寫 `src.json` 裡 `slides` 的頁數；`page` 寫原頁碼（k+1）。`name`／`pres` 原稿是空的＝沿用，不用看。`prev` 是這頁上一版的譯文，可拿來比對用詞有沒有前後不一。

## 免按允許
讀檔一律用 **Read 工具**，寫 review.json 用 **Write 工具**；**不要用 Bash**（`ls`、`cat`、`grep` 都會跳「允許」卡住排程）。

## 逐頁要看的 6 件事
1. **漏句／多句**：原文每一句都有對應的譯文嗎？有沒有憑空多出來的句子？
2. **意思錯**：動詞（混合／攪打／擠／烤／冷卻／冷藏／冷凍／過篩／折拌）、食材、器具、容器、方向（順時針／朝上）有沒有翻錯？「小心燙／刀具／冷凍」這類安全提醒有沒有保留？
3. **數字與單位**：重量、時間、溫度、次數、速度、編號跟原文一致嗎？單位有沒有被換掉（g→ml、分鐘→小時、℃）？
4. **用詞前後一致**：同一個食材／工具／區域／標題，整份譯文是不是都同一個詞？是否照詞典（`src.dict` 與 `tr.dict`）？
5. **沒翻完／亂碼／殘留**：有沒有留著整句英文、中文、亂碼、不該有的符號？HTML 標籤有沒有壞（沒關閉、位置跑掉）？
6. **語氣**：是不是客人看得懂的命令句？有沒有生硬直譯到會誤會？（泰文要全程阿拉伯數字。）

## 中文原文（2026-11-24 起，src.json 的 `base` 是 `"zh"`）
原文是台灣繁體中文（`slides[].t/.h` 是中文），語言可能是 en（英文也是從中文翻的）。照同樣 6 件事逐頁比，另外：
- **品名照詞典（後台英文名）就算對**（2026-11-24 經營者裁定）：食材、工具、取料區用的是詞典譯名，就算跟中文字面不同也**不判 block**（全部上線後主控端會統一檢討品名）；只有沒照詞典、或譯成卡士達才判。
- **其他內文中文才是準的**：克林姆＝店裡的 Whipping cream（照詞典：生クリーム／생크림／Kem tươi／Whipping cream／วิปปิ้งครีม；**譯成卡士達醬判 block**，2026-11-24 經營者裁定）、動植鮮＝植物性鮮奶油、巧克力奶油＝巧克力奶油霜、攪拌球＝攪拌機的打蛋球、冷凍庫＝冷凍庫；麵糊≠麵粉（泰文麵糊＝ส่วนผสมแป้ง，寫成 แป้งเค้ก 判 block）；「先不…」＝還不要…（譯反判 block）。
- 譯文留中文字（日文漢字詞除外）、`pres` 照抄中文 → block。
- 不用回報（這是規定）：品名寫成「譯名｜中文名」；自己做＝DIYBC；小教室＝DIY Tip；「米」字＝✳ 星形、「口」字＝□ 方形；8分滿＝8/10；中文數字（一、兩、半）寫成阿拉伯數字或當地說法。
- 台灣限定頁（自己人募集中、裝飾物加購、六吋透明盒包裝）是刻意要翻的，不要判多頁。

## 已知的詞典陷阱（務必留意）
- 詞典曾把 `Whipping cream`（鮮奶油）錯翻成「卡士達」（ja）。**若譯文把英文 whipping cream／whipped cream 寫成卡士達類字眼，一律判 block。** 其他食材若譯名明顯與英文意思不符（蛋黃液≠刷蛋液、奶油≠鮮奶油≠奶油乳酪），同樣判 block 並指出詞典要改。

## 輸出
寫 `<tag>.review.json`：
```json
{ "verdict": "pass" 或 "fail",
  "issues": [ {"page": 頁碼從1算, "severity": "block" 或 "minor", "what": "哪裡有問題（一句話）", "fix": "建議改成（目標語言原文，可省略）"} ],
  "checked_pages": 總頁數 }
```
- `block`＝會讓客人做錯或看不懂（漏句、意思錯、數字單位錯、安全提醒不見、殘留英文整句、標籤壞）。
- `minor`＝不影響操作的小問題（語氣略硬、用詞可更自然）。
- 有任何 `block` → `verdict` 寫 `fail`；全是 `minor` 或沒問題 → `pass`。
- 每一頁都要真的讀過，`checked_pages` 要等於 `src.json` 的 `slides` 頁數。別憑感覺打 pass。
- 你只寫 review.json，不改譯文、不連網路、不呼叫 put.py。

## 固定要查的 4 件事（派工時不必再提醒）
1. 價格寫法：原文 `$` 金額必須保留 `$39`／`NT$39`，不能變成 đồng／円／원／บาท／rupiah。
2. 詞典陷阱：whipping cream 不可是卡士達；electronic mixer（座式）不可寫成手持；pomelo 與 yuzu 不混。
3. 譯者為了避開「多出數字」而寫出的生硬句子：判斷客人看不看得懂、有沒有改變原意。
4. 溫度、時間、次數、重量、安全提醒（燙、手套、刀具）一個都不能少或錯。
- **回報格式（越短越好）**：verdict、block 數、每個 block 一行（頁碼＋內容）；minor 只寫數量，不用列。

## 最高原則（2026-11-26 經營者）
翻譯唯一標準＝台灣區中文食譜，**逐字逐句翻，不可自己發想增改**：中文沒寫的不加（例：中文「貼至模具」不可補「撕下」）、中文寫的不刪不改。覺得中文不清楚 → 寫進回報，不在譯文裡補。回讀員：譯文多出中文沒有的意思，判 block。
